## Ask
Build the browser workbench per docs/architecture/lld.md §3, §5 and hld.md §1, §4 (Vite root is src/client; vite.config.ts proxies /api and /cascade to :8787). Plain TypeScript + DOM, no framework.
- `index.html` + `main.ts` + `styles.css`: controls (Start/Stop, mode toggle voice-to-voice | cascade usable before and during a session, pair select with en↔es, a headphones hint), two live transcript panes (source, target) per turn with state labels ("not interpreted (translate timeout)", "nothing heard"), a timing panel per turn (to first audio, to end of audio, per-stage bars; in voice-to-voice mode stages show "not observable in this mode"), vendor names from GET /api/config, an Eval button.
- `session.ts`: owns mode, pair, turns (conversation history); switching mode mid-session stops the old transport and starts the new one with the last 5 turns as context.
- `transports/realtime.ts`: POST /api/realtime-session {pair, context} → client secret; WebRTC to OpenAI (`POST https://api.openai.com/v1/realtime/calls?model=gpt-realtime`, SDP offer, Bearer = client secret), data channel "oai-events"; map events (input_audio_buffer.speech_stopped with audio_end_ms → speech_end; conversation.item.input_audio_transcription.delta/completed → srcText; response.output_audio_transcript.delta → tgtText; output_audio_buffer.started → first_audio; output_audio_buffer.stopped → audio_end). Detect source language from text (Spanish chars/stopwords) for labels.
- `transports/cascade.ts`: WebSocket /cascade, AudioWorklet mic capture → PCM16 16 kHz frames, ClientMsg/ServerMsg from src/shared/contracts.ts, clock offset via ping/pong, binary audio frames (4-byte seq + PCM16 24 kHz) to the player.
- `player.ts`: AudioContext queue by seq, never waits on failed/empty turns, barge-in: new speech_end cuts current playback; echo guard: mute mic frames to the transport while our audio plays.
- Errors: mic permission denied → message + Start disabled; ws/WebRTC drop → auto-reconnect once with a "reconnected" notice; server error messages shown on the turn.
- `eval.ts`: Eval button loads GET /api/eval-clips, plays each /eval/clips/<id>.wav as a fake mic (MediaStreamAudioDestinationNode) through the active transport, one clip at a time with a gap, records per-turn timings, texts, state and interpreted audio as WAV base64 (EvalTurnResult), then POST /api/eval-results an EvalRun; shows progress.
Read first: src/shared/contracts.ts, docs/architecture/lld.md, docs/architecture/hld.md, docs/research/R01-realtime-voice-api.md, AGENTS.md.
