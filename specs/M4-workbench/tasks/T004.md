## Ask
Redesign the browser workbench UI (human request at the Try-it check, 2026-10-18): modern, creative, and honest about
what each architecture can measure. Plain TypeScript + DOM + CSS (no new dependencies). Keep every behaviour that works
today (transports, session, player, eval runner, mic-denied handling, reconnect notices).

1. **Siri-style orb** (centre of the page). Reference the human gave: two spheres — idle = a soft pearl sphere, pale
   grey-green, matte with a fine grain; active = an iridescent sphere blending pink, violet, lavender and periwinkle blue
   with soft swirling light and a slight glow. Build it in CSS (layered radial/conic gradients, blur, a grain overlay via
   an inline SVG noise filter or repeating-radial pattern, slow rotation/drift animations) driven by JS-set CSS custom
   properties. States: `idle` (pearl, still), `listening` (iridescent, glow breathes with live mic level — add an
   AnalyserNode/RMS on the mic stream in capture or session and feed `--level` 0..1), `translating` (iridescent, faster
   swirl, stronger violet), `speaking` (iridescent, glow pulses with output level from the player stream), `error` (brief
   warm red tint). Glow must be "slight": soft outer box-shadow/blur, not neon. `prefers-reduced-motion` → no rotation,
   static gradient + opacity change only.
2. **Architecture toggle**: a prominent segmented control "Voice-to-voice | Cascade" (still works before and during a
   session, as now), each segment with a one-line description.
3. **Pipeline view** under the orb, changes with the mode:
   - Cascade: three connected layers, left→right or top→bottom with animated connectors: **Speech-to-text** (vendor name
     from /api/config), **Translate**, **Text-to-speech**. For the current turn each layer shows its state (waiting /
     active with glow / done / failed with reason) and its measured ms (turn detection + STT final, first translation,
     first TTS byte, playback start). Data flows visibly (a moving dot/shimmer along the connector) while a stage is active.
   - Voice-to-voice: ONE sealed layer "gpt-realtime — speech in, speech out" with a lock/black-box treatment and the text
     "internal stages are not observable"; show only what is observable: speech end (approx., VAD silence 500 ms),
     first audio, end of audio.
4. **Metrics terminal**: a monospace, terminal-styled panel (dark, prompt glyphs, blinking cursor, auto-scroll, aria-live
   polite) that streams one line per timing event and per turn result, e.g.
   `23:41:02.120  cascade  t3  stt_final        deepgram   +312 ms` and
   `23:41:04.800  cascade  t3  ✓ first audio 2678 ms  (target < 3000)`; failures in red with the reason. A header block
   prints a live session summary per mode: turns, p50/p95 speech_end→first_audio and speech_end→audio_end, and per-stage
   p50 for cascade only. It must state what is and is not comparable, e.g.
   `# comparable across modes: speech_end→first_audio, speech_end→audio_end (realtime speech_end is approximate)`
   `# cascade only: per-stage timings, source WER   ·   voice-to-voice: stages not observable`.
   Never show a number for a metric a mode cannot measure; print `n/a (not observable)`.
5. **Transcripts**: modern conversation view — per turn a card/bubble with source (small language tag) and target, state
   chips (not interpreted / nothing heard / cut off), newest at bottom, auto-scroll.
6. **Look**: dark, calm, modern (system font stack or Inter via Google Fonts allowed), generous spacing, subtle glass
   panels, consistent accent from the orb palette. Responsive down to 375 px. WCAG 2.2 AA contrast; all controls keyboard
   reachable with visible focus.
