    Design

    A seeded, deterministic model: 20% of sessions voice-to-voice, a turn every 6 s, M/M/c queueing, 429s above each pool's limit. Naive retries every 250 ms with no budget; scaled backs off (200 ms × 2ⁿ, 3 tries) inside a 10% retry budget. Limits are illustrative, not vendor quotes.

    What makes it scale

    • Stateless edges, sticky sessions. The load balancer pins each WebSocket to one Node instance; instances autoscale on session count and drain before deploys.
    • Per-vendor pools. Each vendor gets a pool of keys sized to its concurrency cap; a shared Redis rate limiter and retry budget stop retry storms.
    • Failover per stage. When the Deepgram pool is full, new streams go to OpenAI STT instead of queuing.
    • Voice-to-voice skips our servers. The browser talks to OpenAI Realtime over WebRTC; the API only mints a short-lived client secret.
